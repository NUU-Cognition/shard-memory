# Memory

A Memory is a single, deliberately curated unit of long-term knowledge the workspace chooses to retain — a fact, decision, preference, or convention worth carrying across sessions. It sits at the synthesis-leaning end of the record spectrum: distilled and human-or-agent-vetted, not a raw transcript. Every Memory occupies one of two lifecycle states — **Active** (current, true now, surfaced through the always-loaded index and loaded on demand) or **Log** (an Active memory that went stale and aged out, or a past event recorded straight as history; retained for the record but never auto-loaded). The defining move is that memories are *moved, not deleted*: when an Active memory stops being current it transitions to Log rather than being erased, preserving the trail. A Memory differs from a Note (which is free-form and untyped), a Record (which captures an event without curation), and a Task (which prescribes future work) — a Memory is the curated standing answer to "what should I already know here?"
